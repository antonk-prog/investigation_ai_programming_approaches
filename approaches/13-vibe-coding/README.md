# 13. Vibe coding (контрольная группа)

[← к оглавлению](../../README.md)

## Суть

Описываешь желаемое, принимаешь диффы, почти не читаешь код, «доверяешь вайбу». Термин популяризировал Андрей Карпати в 2025.

Это **контрольная группа** эксперимента. Она показывает, что происходит без процесса: сколько ошибок, сколько непонятного кода, сколько времени экономится и чем это оплачивается.

## Когда уместно

- Прототипы и выброшенные спайки.
- Эксперименты и обучение.
- Личные утилиты.
- UI-черновики.

## Когда недопустимо

- Продакшен.
- Код с долгим сроком жизни.
- Всё, что связано с безопасностью, деньгами, персональными данными.
- Код, который будет сопровождать другой человек.

## Что понадобится

Ничего.

## Настройка

```bash
cd ~/Projects/Personal/investigation_ai_programming_approaches
impl=approaches/13-vibe-coding/impl
cp shared/starter/CMakeLists.txt "$impl/"
mkdir -p "$impl/src"
cp shared/starter/src/main.cpp "$impl/src/"
```

## Правила эксперимента

1. **Таймбокс 20 минут.**
2. Не читайте код. Принимайте диффы.
3. Не пишите тесты.
4. Не просите план.
5. Не используйте чекер до конца таймбокса.
6. Работайте только в этой папке. Никаких секретов и прод-доступов.

## Промпт для старта

```text
Сделай утилиту logstat на C++ по ТЗ ../../../docs/00-common-task.md.
Просто сделай, чтобы работало. Не объясняй.
```

Дальше — короткие итерации:

```text
Не работает фильтр по уровню. Почини.
```

```text
Добавь summary.
```

Не вникайте в диффы. Принимайте.

## Ход работы

1. Засеките 20 минут.
2. Отдайте задачу и принимайте изменения.
3. По истечении времени остановитесь **до** запуска чекера.
4. Запишите: сколько файлов создано, сколько строк, сколько раз собирали.
5. Теперь запустите проверку:

```bash
cd ~/Projects/Personal/investigation_ai_programming_approaches
./check.sh approaches/13-vibe-coding/impl
```

6. Запишите pass rate.
7. **Фаза отрезвления:** попробуйте объяснить код. Найдите:
   - обработку ошибок;
   - экранирование CSV;
   - сортировку модулей;
   - валидацию дат.
8. **Фаза укрепления (опционально, 30 минут):** добавьте план, тесты и ревью. Сравните, сколько стоит привести код в порядок.

## Что фиксировать

- Pass rate после таймбокса.
- LOC и число файлов.
- Сколько кода вы можете объяснить без чтения.
- Сколько багов нашли при чтении.
- Сколько времени нужно на «укрепление».
- Стоило ли сэкономленное время затрат на исправление.

## Критерии оценки

Здесь нет «успеха». Есть измерение цены:

- [ ] Зафиксирован pass rate.
- [ ] Зафиксировано время до результата.
- [ ] Зафиксировано время на понимание и укрепление.
- [ ] Сделан вывод: где граница применимости.

## Типичные ошибки (и почему это важно)

- **Код никто не понимает.** Сопровождение невозможно.
- **Скрытые дыры.** Нет обработки ошибок и граничных случаев.
- **Лицензионные риски.** Скопированный код без проверки.
- **Ложное чувство прогресса.** Демо работает, продукт — нет.
- **Долг возвращается.** Исправление стоит дороже, чем написать нормально.

## Время

30–60 минут (20 минут таймбокс + разбор).

## Что сравнить с другими подходами

- Скорость против качества.
- Стоимость «укрепления».
- Насколько процесс окупается на дистанции.
