# 09. BMAD-METHOD

[← к оглавлению](../../README.md)

## Суть

BMAD имитирует полноценную agile-команду агентами-ролями:

```
Analyst → Product Manager → Architect → Scrum Master → Developer → QA
```

Каждый переход фиксируется артефактом: brief, PRD, архитектура, эпики, истории, QA-отчёт. Это даёт структуру и разделение ответственности, но стоит дорого.

BMAD полезен там, где процесс нужен и так: крупный greenfield, регулируемая среда, аудит. Для маленькой утилиты это стрельба из пушки по воробьям — что тоже полезно проверить.

## Что понадобится

- Node.js 20.12+ (есть 22.23.3)
- Python 3.10+ (есть 3.13.5)
- `uv`

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh

python3 -m pip install --user uv
```

```bash

impl=approaches/09-bmad-method/impl
cp shared/starter/CMakeLists.txt "$impl/"
mkdir -p "$impl/src"
```

Проверьте поддерживаемые инструменты:

```bash
npx bmad-method install --list-tools
```

Берите стабильную ветку **v6.12**. v7 в alpha и может ломаться.

Если opencode нет в списке поддерживаемых инструментов:

- установите для `agents`/`claude-code`, а артефакты читайте вручную;
- либо прогоните BMAD в Claude Code, а код реализуйте в opencode;
- либо ограничьтесь ручным заполнением шаблонов BMAD.

## Ход работы

Полный цикл BMAD для такой задачи — оверкилл. Поэтому **таймбокс 2 часа** и сокращённый маршрут:

1. Brief (10 мин).
2. PRD (20 мин).
3. Архитектура (20 мин).
4. Одна-две истории (15 мин).
5. Реализация (40 мин).
6. QA-чек (15 мин).

Не создавайте все возможные артефакты. Цель — понять цену процесса.

Сборка и проверка:

```bash
cd ~/Projects/Personal/investigation_ai_programming_approaches
./check.sh approaches/09-bmad-method/impl
```

## Что фиксировать

- Сколько артефактов создано.
- Сколько из них вы реально прочитали.
- Сколько времени ушло на процесс против кода.
- Помог ли PRD/архитектура принять решения.
- Сколько токенов ушло (если видно).
- Насколько результат лучше/хуже plan-first при равном времени.

## Критерии успеха

- [ ] Пройден хотя бы brief → PRD → архитектура → реализация.
- [ ] Артефакты не противоречат друг другу.
- [ ] 100% acceptance (или зафиксирована причина, почему не успели).
- [ ] Сделан вывод: где BMAD оправдан, а где нет.

## Типичные ошибки

- **Полная церемония для маленькой задачи.** Утонете в документах.
- **Артефакты ради артефактов.** Если их никто не читает — это налог.
- **Доверие PRD без проверки.** Агент может придумать требования.
- **Расхождение документов.** PRD говорит одно, архитектура другое.
- **Игнорирование QA-роли.** Тогда BMAD даёт меньше, чем обычный TDD.

120–180 минут (таймбокс обязателен).
