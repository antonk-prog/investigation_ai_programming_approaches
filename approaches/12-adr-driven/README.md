# 12. ADR-driven

[← к оглавлению](../../README.md)

## Суть

Архитектурные решения фиксируются короткими записями — Architecture Decision Records. Агент обязан их читать и учитывать. Решения не переобсуждаются без причины.

Формат ADR:

```md
# 0002. Ручной парсер CSV вместо библиотеки
## Context
## Decision
## Alternatives considered
## Consequences
```

Это дешёвая практика, которая особенно хорошо работает с агентами: они склонны «изобретать заново» и нарушать невидимые ограничения.

## Что понадобится

Ничего. Шаблон уже лежит в `impl/docs/adr/0000-template.md`.

Опционально `adr-tools` — для эксперимента не нужен.

## Настройка

```bash
cd ~/Projects/Personal/investigation_ai_programming_approaches
impl=approaches/12-adr-driven/impl
cp shared/starter/CMakeLists.txt "$impl/"
mkdir -p "$impl/src"
cp shared/starter/src/main.cpp "$impl/src/"
```

Создайте `impl/AGENTS.md`:

```md
# Правила

1. Перед архитектурными изменениями прочитай docs/adr/*.md.
2. Не пересматривай принятые решения без нового ADR.
3. Новое архитектурное решение оформляй как docs/adr/NNNN-<title>.md.
4. Ссылайся на ADR в комментариях и коммитах.
```

## Промпт для старта

```text
Прочитай ТЗ ../../../docs/00-common-task.md и docs/adr/0000-template.md.

Работаем через ADR.

1. Создай ADR-0001: язык C++14, CMake, без сторонних зависимостей.
2. Создай ADR-0002: стратегия парсинга CSV (ручной state machine vs split vs библиотека).
3. Создай ADR-0003: модель фильтрации и формат summary.
4. Для каждого ADR укажи минимум одну альтернативу и последствия.
5. Только после этого реализуй logstat строго в рамках ADR.
6. Если по ходу нужна новое решение — сначала ADR, потом код.
```

## Ход работы

1. Напишите 3–4 ADR **до** кода.
2. В каждом должна быть хотя бы одна отвергнутая альтернатива и последствия.
3. Реализуйте в рамках принятых решений.
4. Если хочется отступить — сначала новый ADR, потом изменение.
5. Соберите и проверьте:

```bash
cd ~/Projects/Personal/investigation_ai_programming_approaches
./check.sh approaches/12-adr-driven/impl
```

6. Проверьте: можно ли по ADR восстановить логику решений без чтения кода?

## Что фиксировать

- Сколько ADR создано.
- Сколько решений реально были неочевидными.
- Сколько раз агент пытался нарушить ADR.
- Помогли ли ADR на ревью.
- Сколько ADR устарело к концу работы.

## Критерии успеха

- [ ] ADR созданы до реализации.
- [ ] У каждого есть альтернатива и последствия.
- [ ] Агент не нарушает принятые решения без нового ADR.
- [ ] 100% acceptance.

## Типичные ошибки

- **ADR как пересказ кода.** ADR фиксирует **решение и причину**, а не реализацию.
- **Нет альтернатив.** Если альтернатив не было, это не решение.
- **Слишком длинные ADR.** Один ADR — одно решение, полстраницы.
- **ADR не читаются.** Нужен короткий индекс и правило в `AGENTS.md`.
- **Решения меняются молча.** Тогда ADR превращается в ложь.
