# 03. Context-Driven Development / Conductor

[← к оглавлению](../../README.md)

## Суть

Агент теряет контекст между сессиями. Conductor заземляет его в постоянных файлах проекта:

```
conductor/
├── product.md      # миссия, пользователи, ценность
├── tech-stack.md   # языки, версии, инструменты
├── workflow.md     # стандарты кода, тесты, git
└── tracks.md       # реестр фич и статусов
```

Каждая фича — «трек» со своей спецификацией и планом. Перед реализацией агент обязан прочитать контекст. Это даёт преемственность: новая сессия не начинает с нуля.

## Что понадобится

Плагин opencode:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["opencode-conductor@latest"]
}
```

Положите его в `approaches/03-context-driven-conductor/impl/opencode.json` и перезапустите opencode **в этой папке**.

Плагин сообщества — версию лучше зафиксировать, например `opencode-conductor@1.0.6`, чтобы результат был воспроизводим.

## Настройка

```bash
cd ~/Projects/Personal/investigation_ai_programming_approaches
impl=approaches/03-context-driven-conductor/impl
cp shared/starter/CMakeLists.txt "$impl/"
mkdir -p "$impl/src"
cp shared/starter/src/main.cpp "$impl/src/"
```

Создайте `impl/opencode.json` (см. выше) и перезапустите opencode.

## Промпт для старта

```text
/conductor-setup
```

Заполните созданные файлы **до** начала работы:

- `product.md`: утилита анализа журнала контроллера для инженеров и поддержки.
- `tech-stack.md`: C++14, CMake 3.16+, Ninja, Linux, без сторонних зависимостей.
- `workflow.md`: сборка, тесты, стиль, Definition of Done.
- `tracks.md` не редактируйте вручную, если плагин управляет им.

Затем:

```text
/conductor-new-track Добавить утилиту logstat согласно ТЗ ../../../docs/00-common-task.md
```

После генерации трека:

```text
/conductor-implement
```

## Ход работы

1. Заполните контекстные файлы. Не копируйте ТЗ целиком — это должны быть **факты о проекте**.
2. Создайте трек. Проверьте его spec/plan.
3. Реализуйте.
4. **Закройте opencode и откройте заново.** Продолжите работу. Проверьте, сохранился ли контекст.
5. Соберите и проверьте:

```bash
cd ~/Projects/Personal/investigation_ai_programming_approaches
./check.sh approaches/03-context-driven-conductor/impl
```

6. Обновите статус трека.

## Что фиксировать

- Время на заполнение контекстных файлов.
- Помог ли контекст во второй сессии.
- Сколько фактов оказались неверными или устаревшими.
- Не возникло ли дублирование с ТЗ и AGENTS.md.
- Сколько раз агент обращался к контексту.

## Критерии успеха

- [ ] Четыре контекстных файла заполнены и соответствуют реальности.
- [ ] Трек создан и реализован.
- [ ] Вторая сессия продолжила работу без потери контекста.
- [ ] 100% acceptance.

## Типичные ошибки

- **Копировать ТЗ в `product.md`.** Там нужна миссия, а не требования.
- **Устаревший стек.** Проверьте версии.
- **Раздутые файлы.** Контекст должен быть коротким и точным.
- **Дублирование.** Если факт уже в `AGENTS.md`, не повторяйте его.
- **Плагин не загрузился.** Проверьте путь к `opencode.json` и перезапуск.

60–90 минут.
