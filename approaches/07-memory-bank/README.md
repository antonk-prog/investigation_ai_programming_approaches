# 07. Memory Bank

[← к оглавлению](../../README.md)

## Суть

У агента нет памяти между сессиями. Memory Bank — это набор файлов, которые агент читает в начале сессии и обновляет в конце. Это не энциклопедия, а **рабочая память**.

Типовой набор:

```
memory-bank/
├── projectbrief.md      # что за проект, границы
├── productContext.md    # зачем, для кого
├── activeContext.md     # над чем работаем сейчас
├── systemPatterns.md    # архитектура, паттерны, решения
├── techContext.md       # стек, сборка, ограничения
└── progress.md          # что сделано, что дальше, проблемы
```

## Что понадобится

Ничего. Опционально — расширение **Cline** для VS Code, если хотите оригинальный Memory Bank.

В opencode роль ритуала выполняет проектный `AGENTS.md`.

## Настройка

```bash
cd ~/Projects/Personal/investigation_ai_programming_approaches
impl=approaches/07-memory-bank/impl
cp shared/starter/CMakeLists.txt "$impl/"
mkdir -p "$impl/src"
cp shared/starter/src/main.cpp "$impl/src/"
mkdir -p "$impl/memory-bank"
```

Создайте `impl/AGENTS.md`:

```md
# Правила работы

1. В начале каждой сессии прочитай memory-bank/*.md.
2. В конце каждой сессии обнови activeContext.md и progress.md.
3. Не храни в memory-bank то, что можно узнать из кода.
4. Указывай дату и источник у каждого факта.
5. Если факт устарел — удали или пометь как устаревший.
```

Создайте `memory-bank/projectbrief.md`:

```md
# Проект

Утилита logstat: фильтрация и сводка CSV-журнала контроллера.
Язык: C++14. Сборка: CMake + Ninja. Без сторонних зависимостей.
```

## Промпт для старта

```text
Прочитай memory-bank/*.md и ТЗ ../../../docs/00-common-task.md.

Работаем в две сессии.
Сессия 1:
1. Создай/обнови memory-bank: projectbrief, productContext, techContext, systemPatterns.
2. Составь план реализации и начни его выполнять.
3. В конце обнови activeContext.md и progress.md так, чтобы новая сессия могла продолжить без тебя.

Сессия 2 (после перезапуска):
1. Прочитай memory-bank, восстанови контекст.
2. Продолжи с того места, где остановились.
3. Доведи до 100% acceptance.
```

## Ход работы

1. Заполните bank **до** кода. Коротко и по делу.
2. Начните реализацию.
3. Через 20–30 минут **закройте opencode**.
4. Откройте заново. Ничего не объясняйте — пусть агент прочитает bank.
5. Продолжите. Зафиксируйте, сколько контекста восстановилось.
6. В конце обновите `progress.md`.
7. Проверка:

```bash
cd ~/Projects/Personal/investigation_ai_programming_approaches
./check.sh approaches/07-memory-bank/impl
```

## Что фиксировать

- Сколько фактов в bank.
- Сколько из них реально пригодились во второй сессии.
- Сколько фактов оказались неверными.
- Сколько времени агент потратил на чтение bank.
- Стало ли лучше по сравнению с работой без bank.
- Насколько bank разросся и не пора ли его чистить.

## Критерии успеха

- [ ] Bank создан до кода.
- [ ] Вторая сессия продолжила работу без устных пояснений.
- [ ] В bank нет фактов, которые дублируют код.
- [ ] 100% acceptance.

## Типичные ошибки

- **Bank как свалка.** Чем больше файлов, тем меньше пользы.
- **Устаревшие факты.** Без дат и ревизии bank начинает врать.
- **Дублирование AGENTS.md.** Один факт — одно место.
- **Пересказ кода.** Код и так доступен агенту.
- **Отсутствие ритуала.** Bank обновляется только тогда, когда об этом помнят.

60–90 минут.
