# 02. Common Ground

[← к оглавлению](../../README.md)

## Суть

Агент почти всегда работает на неявных допущениях: «наверное, C++14», «наверное, тесты не нужны», «наверное, Excel — целевой потребитель». Common Ground заставляет эти допущения **проговорить**, классифицировать по уверенности и подтвердить у человека.

Три уровня:

- **OPEN** — догадка, опираться нельзя.
- **WORKING** — рабочая гипотеза, можно использовать с оговоркой.
- **ESTABLISHED** — подтверждено, считаем аксиомой.

Это не методология реализации. После выравнивания посылок вы реализуете задачу обычным plan-first (или любым другим подходом).

## Что понадобится

Команда уже установлена:

```
~/.config/opencode/commands/common-ground.md
```

Она написана под Claude и использует `AskUserQuestion`. В opencode интерактивный опрос может не сработать. Тогда просто попросите:

```text
Проведи common-ground вручную: перечисли допущения по проекту, задай мне вопросы по неоднозначным, запиши результат.
```

## Настройка

```bash
cd ~/Projects/Personal/investigation_ai_programming_approaches
impl=approaches/02-common-ground/impl

mkdir -p "$impl/src"
```

## Промпт для старта

```text
Проведи common-ground для задачи logstat.

Контекст: ТЗ лежит в ../../../docs/00-common-task.md, фикстуры в ../../../shared/fixtures/.
Проект: C++ утилита, CMake, без сторонних зависимостей.

1. Перечисли 6–10 допущений, которые нужны для реализации.
2. Для каждого укажи тип (stated/inferred/assumed/uncertain) и уровень (OPEN/WORKING/ESTABLISHED).
3. Задай мне вопросы только по OPEN и критичным WORKING.
4. После моих ответов запиши итог в ground-файл.
```

Затем:

```text
Теперь реализуй logstat, опираясь только на ESTABLISHED.
Для WORKING — помечай в комментариях/сообщениях, что это допущение.
OPEN не используй без моего подтверждения.
```

## Ход работы

1. Запустите common-ground **до** любого кода.
2. Прочитайте список допущений. Найдите те, которые вы бы не заметили.
3. Ответьте на вопросы. Особенно на те, где ответ меняет архитектуру.
4. Посмотрите на ground-файл:

```bash
cat ~/.config/opencode/common-ground/*/COMMON-GROUND.md
```

5. Реализуйте задачу plan-first-циклом.
6. В конце вернитесь к списку: какие допущения оказались верными? Какие — ложными?

## Что фиксировать

- Сколько допущений сгенерировано.
- Сколько было OPEN и сколько вы подтвердили/опровергли.
- Сколько вопросов агент задал **до** кода.
- Сколько раз пришлось исправлять из-за неверной посылки.
- Помог ли ground-файл в ходе реализации.
- Сколько допущений осталось непроверенными.

## Критерии успеха

- [ ] До кода сформирован список допущений.
- [ ] Ни одно OPEN-допущение не легло в основу решения без подтверждения.
- [ ] Ground-файл создан и содержит историю.
- [ ] 100% acceptance.

## Типичные ошибки

- **Путать с ТЗ.** Common Ground не описывает поведение, он описывает **посылки**.
- **Всё записать в ESTABLISHED.** Тогда смысл теряется.
- **Слишком много вопросов.** Спрашивать надо только то, что меняет решение.
- **Забыть обновить.** Ground-файл гниёт, если его не ревизовать.
- **Дублировать AGENTS.md.** Не храните один факт в двух местах.

45–75 минут.

- Сколько вопросов было задано до кода против после.
