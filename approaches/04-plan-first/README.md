# 04. Plan-first / Plan mode

[← к оглавлению](../../README.md)

## Суть

Сначала исследование и план, потом изменения. Человек одобряет план до того, как агент что-то сломал. Это самый дешёвый способ повысить качество: ошибка в плане стоит минуты, в коде — часы.

## Что понадобится

Ничего. В opencode есть агент **Plan** (переключение по Tab) и режим только для чтения.

Проверьте, что в проекте нет `AGENTS.md`, который разрешает агенту самовольно менять файлы.

## Настройка

```bash
cd ~/Projects/Personal/investigation_ai_programming_approaches
impl=approaches/04-plan-first/impl
cp shared/starter/CMakeLists.txt "$impl/"
mkdir -p "$impl/src"
cp shared/starter/src/main.cpp "$impl/src/"
```

## Промпт для старта

```text
Прочитай ТЗ ../../../docs/00-common-task.md и фикстуры ../../../shared/fixtures/.

Работай в режиме планирования. Файлы не меняй.
1. Исследуй задачу и существующий каркас.
2. Задай вопросы по неоднозначностям.
3. Составь план: шаги, файлы, порядок, способ проверки каждого шага.
4. Укажи риски и что может пойти не так.
5. Закончи планом и жди моего одобрения.
```

После одобрения:

```text
План одобрен. Выполняй по шагам.
После каждого шага показывай, что изменилось и как это проверено.
Если нужно отступить от плана — остановись и объясни почему.
```

## Ход работы

1. Переключитесь на Plan (Tab) или используйте явный промпт выше.
2. Прочитайте план. Хороший план:
   - не длиннее 10–12 шагов;
   - у каждого шага есть проверка;
   - явно перечислены файлы;
   - содержит риски и порядок отката.
3. Если план плохой — правьте **план**, а не код.
4. Одобрите и переключитесь на Build.
5. Соберите и проверьте:

```bash
cd ~/Projects/Personal/investigation_ai_programming_approaches
./check.sh approaches/04-plan-first/impl
```

6. Сравните итоговый дифф с планом: где агент отступил и почему.

## Что фиксировать

- Время на план.
- Количество вопросов до кода.
- Точность плана: сколько шагов совпало с реальностью.
- Сколько отклонений и чем они были вызваны.
- Сколько ручных правок.
- Помог ли план на этапе ревью.

## Критерии успеха

- [ ] План создан и одобрен до изменений.
- [ ] В плане есть проверка для каждого шага.
- [ ] 100% acceptance.
- [ ] Отклонения от плана объяснены.

## Типичные ошибки

- **План-театр.** Одобрять, не читая.
- **План на 50 шагов.** Такой план бесполезен.
- **План без проверок.** Непонятно, когда шаг завершён.
- **Молчаливое отступление.** Агент меняет подход без согласования.
- **Планирование очевидного.** Для багфикса на 3 строки план не нужен.

45–75 минут.
