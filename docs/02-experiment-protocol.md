# Протокол эксперимента

Цель — сравнить **процессы**, а не «кто быстрее напишет CSV-парсер». Поэтому условия должны быть одинаковыми.

---

## Правила честного сравнения

1. **Одно ТЗ.** `docs/00-common-task.md` не меняется между подходами.
2. **Одна модель.** Один провайдер, одна модель, одна версия. Записывайте в WORKLOG.
3. **Чистый старт.** Перед каждым подходом `impl/` содержит только стартовый каркас.
4. **Свежая сессия.** Не переносите контекст из предыдущего подхода.
5. **Таймбокс.** По умолчанию 90 минут. BMAD — 120–180. Vibe — 30.
6. **Не подглядывать.** Не смотрите реализации других подходов до окончания текущего.
7. **Фиксируйте всё.** Промпты, ошибки, ручные правки, время.
8. **Ручные правки разрешены**, но каждую записывайте отдельно: что, почему, сколько времени.
9. **Критерий готовности** — `./check.sh approaches/<NN>/impl` даёт 100% PASS и сборка без ошибок.
10. **Эффект обучения.** Поздние подходы выигрывают от знания задачи. Фиксируйте это в выводах; при возможности меняйте порядок.

## Пошаговый цикл

### 1. Подготовка

```bash
cd ~/Projects/Personal/investigation_ai_programming_approaches

impl=approaches/01-spec-driven/impl
cp shared/starter/CMakeLists.txt "$impl/"
mkdir -p "$impl/src"
cp shared/starter/src/main.cpp "$impl/src/"

cmake -S "$impl" -B "$impl/build" -G Ninja
cmake --build "$impl/build"
./check.sh "$impl"   # ожидаемо: почти всё FAIL, это нормально
```

Зафиксируйте время старта.

### 2. Запуск подхода

Откройте `approaches/<NN>/README.md` и следуйте ему. Не пропускайте шаги настройки: смысл эксперимента — в процессе.

### 3. Работа

- Первый промпт — по шаблону из README подхода.
- Не просите «сразу весь код», если подход этого не предполагает.
- Останавливайте агента, если он нарушает процесс (например, в TDD начинает с реализации).
- Каждые 15 минут коротко записывайте состояние в WORKLOG.

### 4. Проверка

```bash
cmake --build "$impl/build"
./check.sh "$impl"
```

Если не 100% — это результат эксперимента, а не провал. Запишите, сколько времени и итераций потребовалось.

### 5. Дебрифинг

Заполните `WORKLOG.md` и `results/<NN>-<name>.md` по шаблону `results/_template.md`.

Ответьте на вопросы:

- Где подход реально помог?
- Где создал лишнюю работу?
- Что пришлось делать вручную?
- Доверили бы вы этот код в продакшен?
- Повторили бы вы процесс с другим разработчиком?
- Сколько артефактов осталось после работы и нужны ли они?

### 6. Сравнение

Перенесите цифры в `docs/04-comparison.md`. Делайте это **после** прохождения, а не заранее.

## Что считать временем

| Метрика | Определение |
|---|---|
| TTFB | время от старта до первой успешной сборки |
| TTA | время до 100% acceptance |
| TTM | время до ручного ревью и признания кода понятным |
| Human time | время, которое вы реально потратили (без ожидания) |
| Agent time | суммарное время работы модели |
| Rework | время на исправление того, что агент сделал неверно |

## Стоп-условия

Остановите эксперимент, если:

- таймбокс истёк;
- агент зациклился (3 одинаковые неудачные попытки);
- процесс требует инструментов, которых нет и установка занимает больше 20 минут.

В этом случае зафиксируйте состояние, причину и оценку «сколько ещё нужно». Это тоже ценный результат.

---

## Гигиена

- Не давайте агенту секреты, токены, прод-доступы.
- Работайте только внутри `approaches/<NN>/impl`.
- Не коммитьте `build/`, `node_modules/`, `_bmad/`, `_bmad-output/`.
- Перед экспериментами с плагинами делайте коммит — чтобы легко откатиться.
