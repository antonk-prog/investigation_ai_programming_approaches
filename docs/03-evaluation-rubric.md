# Рубрика оценки

Оценивайте каждый подход по 7 измерениям. Шкала 1–5. Ставьте оценки **после** дебрифинга, опираясь на записи, а не на память.

---

## Измерения

### 1. Скорость

| Балл | Критерий |
|---|---|
| 5 | 100% acceptance за <= 30 минут |
| 4 | 30–60 минут |
| 3 | 60–90 минут |
| 2 | 90–150 минут |
| 1 | > 150 минут или не завершено |

### 2. Корректность

| Балл | Критерий |
|---|---|
| 5 | 100% acceptance с первого прогона |
| 4 | 100%, но потребовались 1–2 исправления |
| 3 | 100% после 3–5 итераций |
| 2 | 85–99%, остались известные дефекты |
| 1 | < 85% или нестабильно |

### 3. Качество кода

| Балл | Критерий |
|---|---|
| 5 | Понятная структура, тесты, нет предупреждений, легко сопровождать |
| 4 | Хорошо, мелкие замечания |
| 3 | Работает, но читается тяжело |
| 2 | Сильно запутано, дублирование, нет тестов |
| 1 | Понять и сопровождать невозможно |

### 4. Накладные расходы процесса

| Балл | Критерий |
|---|---|
| 5 | Процесс почти не отнимает времени, артефакты полезны |
| 4 | Небольшие затраты, артефакты пригодились |
| 3 | Заметные затраты, польза неочевидна |
| 2 | Много церемоний, документы не читаются |
| 1 | Процесс ради процесса, результат хуже без него |

### 5. Воспроизводимость

| Балл | Критерий |
|---|---|
| 5 | Другой разработчик повторит без вопросов |
| 4 | Повторит с мелкими уточнениями |
| 3 | Нужны устные пояснения |
| 2 | Сильно зависит от конкретной сессии/модели |
| 1 | Не воспроизводится |

### 6. Когнитивная нагрузка на ревью

| Балл | Критерий |
|---|---|
| 5 | Ревью быстрее обычного |
| 4 | Сопоставимо с обычным |
| 3 | Чуть дольше |
| 2 | Заметно дольше |
| 1 | Ревью превращается в переписывание |

### 7. Переносимость на реальный проект

| Балл | Критерий |
|---|---|
| 5 | Готов внедрять в Инкомсистем завтра |
| 4 | Готов после небольшой адаптации |
| 3 | Нужен пилот и доработка |
| 2 | Сомнительно |
| 1 | Не подходит |

---

## Итоговый балл

Простая версия (равные веса):

```
score = (speed + correctness + quality + overhead + reproducibility + review + portability) / 7
```

Взвешенная версия для компании:

| Измерение | Вес |
|---|---|
| Корректность | 0.20 |
| Качество кода | 0.15 |
| Скорость | 0.15 |
| Переносимость | 0.15 |
| Когнитивная нагрузка | 0.15 |
| Накладные расходы | 0.10 |
| Воспроизводимость | 0.10 |

```
weighted = sum(score_i * weight_i)
```

## Дополнительные метрики (если есть данные)

- Число промптов.
- Число итераций «не то».
- Число ручных правок и их время.
- Количество созданных артефактов и сколько из них реально прочитано.
- LOC реализации.
- Покрытие тестами (если есть).
- Стоимость токенов (если провайдер показывает).
- Количество предупреждений компилятора.

---

## Как не обмануть себя

- Не ставьте 5 за «понравилось».
- Сравнивайте с обычной разработкой без ИИ: стало лучше или просто иначе?
- Отделяйте **результат** (код) от **процесса** (как его получили). Нас интересует второе.
- Записывайте негативные наблюдения сразу, а не в конце.
