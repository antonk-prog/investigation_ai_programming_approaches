# Общее ТЗ: утилита `logstat`

Это **одно и то же ТЗ** для всех 13 подходов. Не меняйте его между экспериментами — иначе сравнение будет нечестным.

---

## 1. Задача

Написать консольную утилиту `logstat` на C++14, которая читает CSV-журнал событий, фильтрует записи и либо выводит их обратно в CSV, либо печатает сводку.

Домен: журнал контроллера (модули `can`, `io`, `power`, ...).

---

## 2. Интерфейс командной строки

```
logstat [OPTIONS] <input.csv>
```

| Опция | Аргумент | Поведение |
|---|---|---|
| `--from` | `YYYY-MM-DDTHH:MM:SS` | включить записи с `timestamp >= from` |
| `--to` | `YYYY-MM-DDTHH:MM:SS` | включить записи с `timestamp <= to` |
| `--min-level` | `TRACE\|DEBUG\|INFO\|WARN\|ERROR` | включить записи с уровнем >= указанного |
| `--module` | строка | точное совпадение модуля (case-sensitive) |
| `--summary` | — | печатать сводку вместо CSV |
| `--strict` | — | любая некорректная запись → ошибка, код 2 |
| `-h`, `--help` | — | краткая справка, код 0 |

Правила:

- Позиционный аргумент `<input.csv>` обязателен (кроме `--help`).
- Неизвестная опция, отсутствие аргумента, лишние позиционные аргументы → код 2.
- Все фильтры применяются одновременно (логическое И).
- `--from`/`--to` включительные.
- Порядок уровней: `TRACE < DEBUG < INFO < WARN < ERROR`.

---

## 3. Входной формат

UTF-8 CSV с заголовком:

```csv
timestamp,level,module,message
2026-10-01T08:00:00,INFO,can,"Controller started"
```

Требования:

- Заголовок обязателен и должен совпадать точно: `timestamp,level,module,message`.
- Ровно 4 поля в каждой записи.
- `timestamp` — строго `YYYY-MM-DDTHH:MM:SS`, без таймзоны, валидная дата и время.
- `level` — одно из пяти значений выше, в верхнем регистре.
- `module` — непустая строка без запятых.
- `message` — произвольный текст.
- Поддерживается RFC 4180 в объёме: поля могут быть в кавычках, внутри кавычек допускаются запятые, кавычка экранируется удвоением (`""`). Переводы строк внутри поля **не требуются**.
- Пустые строки игнорируются и не считаются ошибкой.

### Некорректная запись

Запись считается некорректной, если:

- число полей не равно 4;
- `timestamp` не парсится;
- `level` неизвестен.

Поведение:

- без `--strict`: запись пропускается, в `stderr` печатается предупреждение, счётчик `skipped` увеличивается;
- с `--strict`: утилита завершается с кодом 2 (вывод в stdout не требуется).

Некорректный заголовок или отсутствие файла → код 2 всегда.

---

## 4. Вывод: режим CSV (по умолчанию)

В `stdout` печатается:

1. заголовок `timestamp,level,module,message`;
2. все записи, прошедшие фильтры, в исходном порядке.

Поля экранируются по RFC 4180: если поле содержит запятую, кавычку или перевод строки — оно заключается в кавычки, внутренние кавычки удваиваются. Каждая строка заканчивается `\n`.

Если ничего не прошло фильтры — печатается только заголовок, код 0.

---

## 5. Вывод: режим `--summary`

Печатается ровно в таком формате:

```
total: <N>
by_level: TRACE=<a> DEBUG=<b> INFO=<c> WARN=<d> ERROR=<e>
by_module:
  <module>=<count>
  <module>=<count>
skipped: <M>
```

Правила:

- `total` — число записей, прошедших фильтры.
- Все пять уровней печатаются всегда, даже если count = 0.
- `by_module` — только модули, у которых есть хотя бы одна прошедшая фильтры запись.
- Сортировка модулей: по count по убыванию, при равенстве — по имени по возрастанию.
- `skipped` — число некорректных записей во всём файле (не зависит от фильтров).
- Отступ перед строкой модуля — ровно два пробела.
- В конце — перевод строки.

Пример для `shared/fixtures/sample.csv` без фильтров:

```
total: 12
by_level: TRACE=1 DEBUG=2 INFO=4 WARN=2 ERROR=3
by_module:
  io=5
  can=4
  power=3
skipped: 0
```

---

## 6. Коды возврата

| Код | Значение |
|---|---|
| 0 | успех (в том числе 0 совпадений) |
| 2 | ошибка использования, ввода-вывода или данных |
| 1 | зарезервирован |

При коде 2 в `stderr` должно быть непустое сообщение.

---

## 7. Ограничения

- Язык: **C++14**.
- Сборка: CMake >= 3.16, генератор Ninja, один бинарник `logstat`.
- Никаких сторонних runtime-зависимостей. STL + стандартная библиотека.
- Linux, без сети во время работы.
- Чтение входного файла — построчно/потоково; не требуется загружать всё в память (но допустимо для тестовых объёмов).
- Предупреждения компилятора `-Wall -Wextra` желательно не иметь.

## 9. Что НЕ входит в задачу

- Часовые пояса, парсинг `Z`/смещений.
- Переводы строк внутри CSV-полей.
- Несколько входных файлов, stdin, сжатие.
- Конфиг-файлы, локализация.
- Цветной вывод, прогресс-бары.
- Оптимизация под гигабайты (но потоковое чтение приветствуется).
- Веб-интерфейс, БД, сеть.
